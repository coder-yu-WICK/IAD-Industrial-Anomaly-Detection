## 4. 评分标准详解（满分 100）

### 4.1 算法性能（50 分，核心）

| 指标 | 分值 | 说明 |
|---|---|---|
| 像素级 F1 / AP | **25** | 像素级定位精度，**主指标** |
| 图像级 F1 / AP | 15 | 图像级"有无缺陷"判别 |
| 像素级 AUROC | 10 | 阈值无关的稳健性，参考指标 |

**归一化计分**：`score = M × metric_k / metric_best`
（`M` = 该子项满分，`metric_k` = 你的值，`metric_best` = 全场最优值）

> 直觉：不是"达到某个绝对值"，而是"尽量接近第一名"。异常检测中异常样本远少于正常样本，**F1/AP 比 AUROC 更能拉开差距**，故权重最高。

### 4.2 部署成本（30 分，"越小越好"）

| 指标 | 分值 | 规则 |
|---|---|---|
| 训练耗时 | 8 | 按"总耗时 ÷ 类别数"计分，越短越高 |
| 推理耗时 | 12 | 单张端到端（含前后处理），**硬约束 ≤100ms，超时计 0 分** |
| 资源占用稳定性 | 10 | 推理峰值显存 **≤24GB**，且无异常抖动 |

### 4.3 技术先进性（20 分）

| 指标 | 分值 | 获取难度 |
|---|---|---|
| 方案创新性 | 8 | 评委评报告，主观 |
| **Transformer 架构加分** | **5** | ✅ 选对方法就有 |
| **多类别泛化（单模型多类）** | **2** | ✅ 设计成单模型即可 |
| 代码完整性与可复现 | 5 | 可运行 + 文档全 + 3 次跑分波动 ≤2% |

## 5. 核心技术约束（严格执行）

1. 算法范式统一为**无监督异常检测**（训练只用正常样本），不限制具体实现；
2. 允许使用 **ImageNet / DINOv3 / CLIP** 等公开通用预训练权重；
3. 鼓励 **Transformer 架构**（有加分）；
4. **严禁**使用 Omni-AD 以外的工业异常检测数据做预训练/微调；
5. 测试阶段**禁止**使用任何异常样本标注信息（防数据泄露）。

## 7. ⚠️ inference.py 接口规范（命门）

评审组会 **直接调用 `inference.py`** 在统一测试集上批量跑分。接口不对 = 跑不出分。

- **输入**：图像路径（`str`）**或** numpy 数组（`np.ndarray`, H×W×3）
- **输出**：
  - 像素级异常热图：与输入**同尺寸**的 `float` 数组（`shape == (H, W)`）
  - 图像级异常分数：`float`

**易踩坑**：
1. 热图尺寸必须和原图一致（特征图上采样回来）；
2. 热图是 `float` 数组（不是 0/1 二值），分数是 `float`（不是 tensor）；
3. 权重用 `state_dict` 加载，路径通过参数传入，不写死；
4. 支持 CPU/GPU 自动切换（评审机不确定有无 GPU）。

## 8. 组队与晋级规则（3 人）

- 支持个人或小组（**小组上限 3 人**，不接受 3 人以上）；
- 技术文档中须**标注每位成员的详细分工与贡献占比**；
- **晋级名额不以团队整体核定**：评审结合团队跑分 + 个人实际贡献综合评判，**成员不一定全部晋级**，仅对贡献达标者发放名额。

> 结论：**每个人都要有实打实、可量化的贡献**（commit 记录、报告章节、模块代码），避免"搭便车"被刷。

## 10. 关键风险与规避

1. **inference.py 接口不对** → 直接 0 分。→ 拿到数据第一时间先跑通接口。
2. **推理 >100ms** → 该项 0 分。→ 选轻量模型，全程盯着耗时。
3. **显存抖动** → 扣分。→ 关 `cudnn.benchmark`、固定 batch=1、预热一次。
4. **数据保密** → 签协议、数据不进 Git（已 gitignore）、不外传。
5. **学校信息** → 代码/报告/commit 里都不出现学校名。
